# 安全模型（Security Policy）

## 设计边界（先说清楚防什么、不防什么）

**防**：
- 平台内智能体（助手/调度/组长/工人岗）越权：改平台代码、改自己档位、摸密钥、绕过确认。
- 宿主上其他非管理员进程摸到密钥明文（DPAPI 用户态加密 + 五级密钥隔离）。
- 浏览器侧脚本偷登录态（HttpOnly Cookie + 同源代理，无跨站凭证泄漏面）。
- 拿到密钥的脚本顺手换掉找回密码通道之外的暴力枚举（限频 + 审计）。

**不防**（单机自托管模型的诚实边界）：
- 持有 Windows 管理员权限的人——他能读一切，这是操作系统的边界不是本项目的。
- 宿主本身被植入恶意软件。
- 把端口暴露到公网——**请勿这样做**，本设计假定 127.0.0.1 / 内网可信环境。

## 密钥体系（五级隔离）

| 密钥 | 用途 | 存放 |
|---|---|---|
| Admin | 管理端写操作、登录态 | DPAPI `token.bin`（宿主 m-guard 目录），浏览器侧为 HttpOnly Cookie |
| WEBHOOK_TOKEN | 进程内派活/汇报内部通道 | 容器 env |
| SANDBOX_TOKEN | 沙箱执行通道 | 容器 env（沙箱容器不可达管理端） |
| PROXY_TOKEN | CodeBuddy/识图/RAG 代理门 | 容器 env + 前端按需 |
| M_GUARD_KEY | 与 m-guard 守卫通信 | 宿主 env（平台容器独有） |

- 管理密钥与登录密码**只**存在于宿主 DPAPI 加密存储（`token.bin` / `password.bin`），
  容器、前端、日志、设置导出里都没有明文。
- 找回登录（`/auth/login`）验证密码后**不轮换**密钥，只把当前密钥种回 Cookie——
  改密码走独立端点且必须验旧密码或持密钥证明（两条证明路径，与 `/set` 同权限面）。
  （守卫进程内部签发通道语义不同：验密通过后重签发新凭证、明文只回一次——该通道带内部钥匙，不对浏览器直接暴露。）

## 应用层防线

- **确认门四档**（plan/strict/auto_edit/full）：变更类工具按档拦截；执行/删除/发信/派活类
  危险工具**只认外部批准**，批准绑定参数指纹（批完换参数=重新拦截，重试不放行）。
- **自锁守卫**：写工具指向平台源码/档位/密钥路径一律拒绝，任何档位（含 full）不豁免；
  物理兜底=源码卷只读挂载。
- **网关门禁**：写端点 401 门、滑动窗口限频、请求体 64KB 上限、审计日志三代轮转。
- **同源代理**：前端所有后端调用走同源 `/lg` 路径（Next.js rewrites），
  Cookie 不跨站、不暴露 CORS 面。
- **沙箱隔离**：`execute` 默认落在 sandbox 容器，网络上不可达管理端与宿主服务。
- **技能哈希锁**：技能目录与基线不符即整体停用（宁可不带技能，不带未知变更）。

## 报告漏洞

请勿公开提交含利用细节的 Issue。
首选通道：仓库页 **Security → Report a vulnerability**（GitHub 私密漏洞报告，仅维护者可见）。
若该通道暂未启用，请开一个只写「发现安全问题+联系方式」的 Issue，细节由维护者私信跟进。
预期 72 小时内回应；修复后会鸣谢报告者（除非希望匿名）。
