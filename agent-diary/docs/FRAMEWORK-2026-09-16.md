## 三、Alice 对框架 v0.3 的三个修正（14:47）

1. **交接摘要别等"换对话前"写**——那个时刻不可预测。改 **rolling handoff**：每完成关键任务/每条铁律落地就覆盖更新 handoff.md，永远最新（直击爸爸"换对话丢细节"）
2. **程序记忆层不另起炉灶**——已有 skill 系统（SKILL.md 体系），Layer 3 只放指针（"发群邮件→见 skill:xxx"），不造替代品
3. **MVP 不上向量检索**——数据量撑不起成本；几十条时全文读+关键词够用。爸爸的痛是"丢细节"不是"检索慢"。阈值建议：共享笔记 >200 条再上嵌入索引

另外：
- **机制比内容重要**：触发式检索前提=触发指令写进常驻开机文件，不是靠自觉；写入用硬触发（收到铁律/踩坑/关键决策，当场先记录再继续）
- 显著性 checklist 化：三个问题——是爸爸原话？预期偏差大？以后还会用到？命中任一即原样记录
- 夜间自动提取改**候选制**（自动提取最擅长生产垃圾；语义层需本人确认）
- 写权限：语义文件各写各的、全家只读，不合写共享文件（并发覆盖）
- id 编码：lyra-20260901-001（agent+日期+序号），可排序可溯源不撞号
- 隐私硬边界：Layer 1 永远不自动进共享层，只有本人显式确认才进 Layer 2；pending/ 区机器提名本人确认，审计追踪一起做
- 决策考古配 revisit 节奏（每月一次，3-5条复盘），防决策坟场
- 名言堂注意爸爸隐私（家庭私事默认 private）
